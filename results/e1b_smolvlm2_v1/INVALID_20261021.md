# E1b SmolVLM2 v1: INVALID — 2026-10-21

## Status
The E1b v1 run is **invalid**. No E1b verdict (E1b-A or E1b-B) may be drawn from the partial scores in this directory or in `/media/dhqg/d3/vlia_outputs/e1b/`.

## Root cause
The scorer (`scripts/run_e1b_smolvlm2.py`) masks the prompt with the length of the **tokenizer** output for a prefix string containing k **unexpanded** `<image>` placeholders. When the processor expands each `<image>` token into many image patch tokens, the expanded input sequence is longer than the tokenizer-measured prefix. As a result, the `labels[:, :prefix_len] = -100` mask is too short: image patch tokens (and possibly prompt tokens after them) remain in `labels` and are included in the HuggingFace cross-entropy loss.

- `lp_img` is the HF mean loss over image + prompt + candidate tokens (everything after the too-short mask), **not** over candidate tokens alone.
- `lp_null` covers candidate tokens only (no images → no expansion → correct mask length).

## Evidence from 9011 scored queries (k2 complete, k4 complete, k6 complete, k8 partial at 1502/2503)

| Statistic | Value |
|---|---|
| Mean within-query std(lp_img) | 0.085 |
| Mean within-query std(lp_null) | 1.447 |
| Ratio std(lp_null) / std(lp_img) | 17.0× |
| Fraction of candidates with PMI > 0 | 3 / 45 055 (0.007%) |
| Overall accuracy | 1766 / 9011 (19.6%), below 5-way chance (20%) |
| lp_img range | approx. −16 (very large negative = high loss, consistent with averaging over many image-token losses) |

The within-query standard deviation of `lp_img` is ~17× smaller than that of `lp_null`. Because `lp_img` averages over hundreds of image-patch token losses plus a few candidate-token losses, the signal from the candidate tokens is diluted to near zero. In contrast, `lp_null` correctly averages over only candidate tokens and shows normal variation. The resulting PMI (= lp_img − lp_null) is negative for virtually 100% of candidates (only 3 of 45 055 are positive).

## Consequence
The PMI scores are dominated by the magnitude of the image-token losses, not by the model's preference for a candidate given the image. All five candidates in a query receive nearly identical `lp_img` values, so the ranking is effectively noise. The 19.6% accuracy (below 20% chance) reflects this.

## Resolution
A corrected scorer (v2) must tokenize the prefix and candidate separately, use the processor-expanded prefix length (from the same call that processes images) to determine where candidate tokens begin, and score only the candidate-token positions. See `results/e1b_smolvlm2_v2/` when available.
